# すごろくサーバーの起動・再起動

1つのスクリプトで両方を行う。

- 動いていない → 起動する
- 動いている → 止めてから起動し直す（Python側の変更が反映される）

再起動するとゲームの進行状態（参加者・所持金・ターン）は消える。
HTML・JS・CSS だけの変更なら再起動は不要（キャッシュ無効で配っているので、ブラウザの再読み込みで反映される）。

## 1. スクリプトを実行する

PowerShell ツールで、プロジェクトのルートから次を実行する（初回は venv 作成と依存インストールで数分かかるので timeout は 300000 にする）。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\.claude\skills\run-server\run.ps1
```

スクリプトがやること:

- ポート（`config.py` の `PORT`）が待ち受け中なら、`/stop-server` の `stop.ps1` で止める
  - それでもポートが空かなければ、このゲーム以外のプロセスが使っている。止めずに `STATUS=error` を返す
- `.venv` がなければ作って依存をインストールする
- `main.py` を**ウィンドウなし**で起動し、待ち受けるまで最大30秒待つ
  - Claude のセッションが終わってもサーバーは動き続ける
  - 出力はログファイル（`LOG`）に書かれる。ターミナルのQRコードは出ないが、PC画面にQRが表示される

出力は `KEY=VALUE` の行:

| キー | 値 |
|---|---|
| `STATUS` | `started`（起動した） / `restarted`（止めて起動し直した） / `error` |
| `HOST_URL` | PC画面のURL |
| `JOIN_URL` | スマホ参加用のURL（LAN IP） |
| `NETWORK` | 使っているネットワークの種類（`Private` / `Public` など） |
| `LOG` | サーバーのログファイル |
| `MESSAGE` | `error` のときの理由 |

## 2. 結果をユーザーに伝える

`STATUS` が `started` または `restarted` のときは、次の形で**Markdownリンク**として表示する（URLはスクリプトの出力をそのまま使う）。

```markdown
サーバーを起動しました。（restarted のときは「サーバーを再起動しました。開いているページは再読み込みしてください。」）

- PC画面: [HOST_URL](HOST_URL) （スマホ用のQRコードもここに出ます）
- スマホ参加: [JOIN_URL](JOIN_URL)

止めるときは `/stop-server` を使ってください。
```

補足を付ける条件:

- `NETWORK` が `Public` のとき: スマホから繋がらない可能性が高い。管理者PowerShellで `setup-firewall.ps1` を実行するよう案内する（手順は README の「Git Bash から」を参照）。勝手に実行しない（管理者権限の変更なので、ユーザーの確認が要る）
- `JOIN_URL` が `127.0.0.1` のとき: ネットワーク未接続。Wi-Fi を確認するよう伝える
- `STATUS=error`:
  - `MESSAGE` がポートを別のプロセスが使っている旨なら、そのまま伝える（このゲーム以外のプロセスは勝手に止めない）
  - それ以外は `LOG` のファイルを Read して、原因をユーザーに伝える
