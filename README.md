# すごろく（Windows親機 ⇄ iOS / Android）

PCの画面に盤面を出し、手元のスマホでサイコロを振って遊ぶ。
スマホ側はブラウザだけ。アプリのインストールは要らない。

## 起動

**`run.bat` をダブルクリック**するのが一番簡単です。
初回のみ venv 作成と依存インストールが走ります（`run.bat` が自動でやります）。

### Git Bash から

プロジェクトのフォルダで実行します。

**1. セットアップ（PCごとに初回だけ）**

`.venv` は git に含まれず、別のPCからコピーしても動かないので、PCごとに作ります。

```bash
# 仮想環境を作って依存をインストール
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt

# スマホ連携（../game_common）を import できるようにする
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ../game_common/install.ps1 .

# スマホから繋がるようにファイアウォールを設定（管理者PowerShellが別ウィンドウで開く）
powershell.exe -NoProfile -Command 'Start-Process powershell -Verb RunAs -ArgumentList ("-NoProfile -ExecutionPolicy Bypass -NoExit -File `"" + (Resolve-Path setup-firewall.ps1) + "`"")'
```

- 「このアプリがデバイスに変更を加えることを許可しますか？」には「はい」
- 開いたウィンドウで `Private` と `GameServer 8000 (Private)` が出れば成功。ウィンドウは閉じてよい（設定は残る）

**2. 起動（毎回）**

```bash
./.venv/Scripts/python.exe main.py
```

止めるときは `Ctrl + C`。ゲーム中はこのターミナルを閉じないこと。

### PowerShell から

```powershell
# 実行ポリシーの制限を受けないよう -File で呼ぶ
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

起動するとターミナルにQRコードと2つのURLが出ます。

- **PC画面** `http://localhost:8000/host` をブラウザで開く（QRもここに出ます）
- **スマホ** 同じWi-Fiに繋いだ状態でQRを読む

## あそびかた

1. PCで `/host` を開く → 右上が緑の「サーバー接続済み」になる
2. スマホでQRを読む → 名前を入れて「参加する」
3. 全員そろったら **「ゲーム開始」** を押す。
   PC画面からでも、**スマホからでも**開始できる
4. 手番の人のスマホに **「サイコロをふる」** が出る。押すと3Dサイコロが回り、
   出目が決まるとコマが1マスずつ進む（PC・スマホの両方で音が鳴る）
   - **カードマス**に止まるとカードが1枚もらえる。手札はスマホの下に並ぶ。
     カードを**タッチすると効果の説明**と「つかう」ボタンが出る
   - カードマスでは**パーツ**（右翼・左翼・エンジン）が出ることもある。3種類そろえると
     「登る」ボタンが出て、1階層上（地上 → 天空 → 宇宙）に登れる
5. **最上階（宇宙）でもパーツを3種類そろえると「天国へ旅立つ」でクリア**。その時点でゲームが終わり、
   所持金が一番多い人の勝ち（旅立った人とは限らない）。
   ターン数の決まりは無いので、誰かが旅立つか、誰かが「ここで終了」を押すまで続く。「もう一度あそぶ」で再戦できる
   - 途中でやめたいときは **「ここで終了」**（PC画面）/ **「ゲーム終了」**（スマホ）。
     その時点の所持金で順位が決まる

PC画面は状況で3つの見た目に変わる。

| いつ | PC画面 |
|---|---|
| 開始前 | QRコードと参加URLだけを大きく出す（盤はまだ出さない）。参加した人は名前のチップで並ぶ |
| 遊んでいる間 | 盤を画面いっぱいに出す。右側に全員の順位・所持金 |
| 終了後 | 盤と結果を出したままにする。右下の「ゲーム終了」を押すと、**参加用のQRコードを前面に大きく出す** |

ゲームが終わっても、QRコードは**自動では出ない**。結果を見終わって
「ゲーム終了」を押したときだけ、参加用のQRコードとURLが前面に出る。次のゲームに
誘うためのもの。`Esc` か画面のどこかを押せば閉じられる。もう一度始めれば自動で引っ込む。

盤を出しているあいだは、**左のバー**に音のオンオフと接続状態が出る。

スマホは**所持金を一番大きく**出し、その下に**順位**（1位は金色）と**階層**を並べる。

PC画面の右側には全員の **所持金と順位**（多い順）が出る。
スマホには **自分の所持金・順位・階層** が出る。

### ルール

- 盤をぐるぐる回る。**上の階層ほど盤が広い**（地上30マス、天空40マス、宇宙50マス）。
  最後のマスの次は `0` のスタートに戻る
- 階層は **地上 → 天空 → 宇宙** の3つ。全員が地上から始める。階層は人ごとに違い、
  **盤（マスの内容）も階層ごとに違う**。人は自分がいる階層の盤を歩く
- **上の階層ほどお金の桁が1つ増える**（地上 ×1、天空 ×10、宇宙 ×100）。
  給料・半周ボーナス・マスの金額のすべてにかかる。所持金の初期値にはかからない
- **最上階（宇宙）でパーツを3種類そろえて「天国へ旅立つ」とクリア**。旅立った瞬間にゲームが終わる
- 全員 **1,000円** を持って始める
- 手番は参加した順。出目は 1〜6。**ターン数の決まりは無い**（ゴールか「ここで終了」まで続く）
- **スタートを通過する（ちょうど止まるのも含む）と +200円**（天空 +2,000円、宇宙 +20,000円）
- **半周するごとに +1,000円**（天空 +10,000円、宇宙 +100,000円）。盤のちょうど真ん中のマス
  （地上 `15`、天空 `20`、宇宙 `25`）がそのための専用の「半周」マス。
  ぴったり止まらなくても、出目やワープで通り過ぎるだけでもらえる
- 止まったマスの効果
  - **もらう** その金額が増える
  - **はらう / ぜいきん** その金額が減る（0円より下にはならない）
  - **ワープ** その数だけさらに進む（スタートを越えれば給料）
  - **もどる** その数だけ下がる（スタートを越えて戻っても給料は出ない）
  - **一回休み** 次の自分の番を飛ばす
  - **カードをひく** カードを1枚もらう。パーツもここで出る（地上は `1, 7, 8, 13, 14, 19, 20, 25` の8マス）
  - **半周** 通過でもらえる大金の専用マス（止まっても、ほかの効果は無い）
- 所持金の多い順に順位がつく。同じ額なら同じ順位（1位, 1位, 3位）
- 勝つのは、天国へ旅立った時点（途中で「ここで終了」したときはその時点）で
  所持金が一番多い人。旅立った人が勝つとは限らない

### スマホからルールを見る

スマホ画面の右上の **「📖 ルール」** を押すと、ルールがポップアップで開く。
ゴールと勝ち方・あそびかた・お金・マスの効果・階層とパーツ・カードの6項目で、中だけスクロールする。
「とじる」・背景のタップ・`Esc` で閉じる。文章は `shared/rules.js` が `state` から作るので、
給料や手札の上限などの数字を変えても、説明は自動で追いつく（カードの種類の説明だけは文章で書いてある）。

### 階層ごとの盤

| 階層 | マス数 | 倍率 | 盤の特徴 | マスの呼び名 |
|---|---|---|---|---|
| 1 地上 | 30 | ×1 | 小さな金額。カードマスは8つ | もらう / はらう / ワープ / もどる / 一回休み |
| 2 天空 | 40 | ×10 | 追い風・向かい風で大きく動く。カードマスは9つ | たから / おとしもの / おいかぜ / むかいかぜ / くもで休み |
| 3 宇宙 | 50 | ×100 | 当たり外れが大きい。カードマスは10 | ほうせき / いんせき / ワープ / ブラックホール / むじゅうりょく |

スタートは `0` マス目、半周は盤の真ん中（マス数 ÷ 2）。
マス数は `game/board.py` の `SIZES`（偶数にすること。盤を輪に並べるため）、
マス配置は `LAYOUTS`、倍率は `SCALES`、呼び名は `NAMES` で決まる。
登ってもマスの位置は変わらない。上の階層の盤は広いので、番号はそのまま新しい盤に収まる。
PC画面の盤の形は階層で違う。

| 階層 | PC画面の盤 |
|---|---|
| 1 地上 | 四角い輪（今までどおり） |
| 2 天空・3 宇宙 | **くねくねした輪**。円形のマスを、うねる曲線に沿って等間隔に並べる。最後のマスの次は0マス目に戻り、ぐるっとループする |

くねくねの盤は `shared/ring.js` の `windingLayout()` が、盤の大きさ（ピクセル）から配置を決める。
うねり方は `WINDING`（`waves` は山の数、`amp` は振れ幅）で、階層ごとに変えてある。
曲がりがきついところでも重ならないように、マスの大きさは自動で小さくなる。
画面の大きさが変わったら描き直す。0マス目は左上で、時計回りに進む。
四角い輪の盤で41マス以上になる場合は、PC画面の文字とコマを少し小さくして収める。
開始時の所持金 `START_MONEY`、給料 `SALARY`、半周ボーナス `HALF` / `HALF_BONUS`（どちらも地上での額）も同じファイルにある。
PC画面の盤は、いま手番の人がいる階層のものを出す（別の階層にいる人のコマはその盤には出ない）。

### カード

**持っているカードは持ち主にしか見えない。** 他の人とPC画面には**枚数だけ**が見える。

| カード | 効果 | つかい方 |
|---|---|---|
| **+1マス / +2マス / +3マス** | 次にふるとき、出た目にその数を足して進む | 自分の番に「つかう」 |
| **サイコロ2個** | 次にふるとき、サイコロを2個ふって合計だけ進む | 自分の番に「つかう」 |
| **おまもり** | はらうマスに止まっても、1回だけ払わずにすむ | **持っているだけで自動**。ボタンは出ない |

- 手札は **3枚まで**（`game/cards.py` の `LIMIT`）
- 4枚目をひくと溢れる。**1枚を選んで捨てるまで、その人はサイコロをふれない**
  （捨てるのは自分の番でなくてもよいので、他の人の番のうちに片付けられる）
- 使ったカードは消える。効果は「次にふる1回」だけで、ふると使い切る
- 「+2マス」と「サイコロ2個」は同じ番に重ねて使える（2個ふって合計 +2マス）
- サイコロが既に2個のときに2枚目の「サイコロ2個」を使おうとしても、無駄にならず手札に残る
- 使った瞬間とおまもりが発動した瞬間は、全員に見える（効果は隠しようがないため）
- カードの種類と出やすさは `game/cards.py` の `DECK` で決まる。山札は減らない（同じカードが何度でも出る）

### 階層とパーツ

上の階層へは、**パーツを3種類（右翼・左翼・エンジン）1つずつそろえて**登る。

- パーツは**カードマスで、カードと同じ山札から**ランダムに出る（`game/cards.py` の `PART_COPIES`）
- パーツは手札とは別に持つ。**手札の上限（3枚）には数えず、捨てることもできない**
- 3種類そろうと、自分の番の間だけ **「登る」** ボタンが出る。押すと各1つが消えて、
  **自分だけ**1階層上に行く（マスの位置はそのまま。余ったパーツは残る）
- 登っても手番は終わらない。そのままサイコロをふれる
- 何を持っているかは本人だけに見える。全員に見えるのは**階層と、パーツの個数**だけ
- 最上階では登る先が無いので、パーツをそろえると**天国へ旅立ってクリア**。パーツも消える
- PC画面のコマは階層で縁の色が変わる（地上は縁なし、天空は青、宇宙は金）

**天国に着くまでは長い。** パーツが9個以上（同じパーツが重なれば、もっと）要るので、
乱数で試したところ（天空40・宇宙50マスの盤で）、1人あたりの振る回数は、1人プレイで中央値112回（36〜274回）、
3人プレイで中央値82回（31〜167回）かかった。
長引くときは、「ここで終了」で区切る。パーツの出やすさは `PART_COPIES` で変えられる。

### 途中の出入り

- ゲームが終わったあと、PC画面の「ゲーム終了」を押すとQRが大きく出るので、次のゲームからは誰でも入れる
- 遊んでいる最中に呼びたいときは、PC画面で「ここで終了」してから「ゲーム終了」を押す
- 手番の人が抜けても、次の人に自動で回る
- スマホの「退出する」、PC画面の各行の「切断」でいつでも抜けられる
- 全員抜けると開始前の状態に戻る

## 繋がらないときは

| 症状 | 原因と対処 |
|---|---|
| スマホでページが開かない | **同じWi-Fiにいない**のが大半。スマホのモバイル通信をオフにして確認 |
| 同上 | ファイアウォール。`setup-firewall.ps1` を管理者PowerShellで実行（設定は永続化されるので通常は1回だけ） |
| 同上 | 別のWi-Fiに繋ぎ替えた場合、そのネットワークが「パブリック」だと再びブロックされる。`setup-firewall.ps1` を再実行すれば直る |
| ターミナルのIPが `127.0.0.1` | ネットワーク未接続。Wi-Fi/有線を確認 |
| ゲストWi-Fi / 社内Wi-Fi | 端末間通信がブロックされている（AP isolation）。スマホのテザリングにPCを繋ぐと回避できることが多い |
| iOSで画面ロック後に反応しなくなる | 対処済み。復帰時に自動再接続します（1秒以内） |
| PC画面から音が出ない | ブラウザは操作があるまで音を鳴らせない（読み込み直後の AudioContext は `suspended`）。画面を一度クリックすれば鳴る。鳴らせない間は画面下に案内が出る |

## 構成

通信とゲームのルールを分けてある。ゲームを作り込むときに触るのは `game/` だけ。

スマホ連携（LAN IP・QR・HTTP・WebSocket・再接続）はこのフォルダには無い。
他のゲームと共有する [`../game_common`](../game_common/) に移してある。

```
main.py            起動するだけ（Game を共通側に渡す）

game/              ゲームのルールと状態  ← ここを育てていく
  logic.py           Game クラス。手番・ターン・サイコロ・マスの効果・カード・順位
  board.py           盤面の定義（マス数と特殊マス、所持金と給料の額）
  cards.py           カードの種類と山札（枚数の上限もここ）

static/
  host.html          PC画面（盤面・サイコロ・参加者一覧）
  player.html        スマホ画面（サイコロを振る）
  shared/            両画面で使う部品  ← 見た目や音を直すのはここ
    format.js          画面に出す文字（位置・出目・金額・順位・階層・カード）
    dice.js            3Dサイコロ
    sound.js           効果音（WebAudioで合成。音声ファイル不要）
    anim.js            1マスずつの移動、状態の順番待ち
    dice.css           サイコロの見た目
    stages.css         階層ごとの背景（地上・天空・宇宙）
    ring.js            盤の並べ方（1層目の四角い輪、2層目以降のくねくねした輪）
    rules.js           ゲームルールの文章（スマホの「ルール」ポップアップ。数字は state から作る）
    audio/bgm.ogg      BGMの曲（PC画面だけで流す。遊んでいる間だけ）

tests/
  test_game.py       ゲームロジックの単体テスト（サーバー不要）
  js/shared.test.mjs 共有部品の単体テスト（ブラウザ不要）

../game_common/         スマホ連携  ← ゲームを増やしても基本さわらない
  mobilelink/
    events.py        「誰に何を送るか」の表現
    protocol.py      ゲーム側が満たす約束ごと（下の5つ）
    server.py        HTTPとWebSocketの入り口
    hub.py           接続の保持とイベント配信
    network.py       ポート番号・LAN IP・参加URL
    qr.py            参加用QRコード
    launcher.py      起動とターミナル表示
    static/conn.js   ブラウザ側の接続（切れたら繋ぎ直す）
```

共通側がすごろくについて知っているのは、`Game` が持つ次の5つだけ。

| メソッド | いつ呼ばれるか |
|---|---|
| `state()` | 繋いできた画面に、いまの状態をまるごと渡すとき |
| `add_player(name)` | スマホが1台参加したとき |
| `remove_player(id)` | 切断・退出したとき |
| `handle(id, msg)` | スマホから1件届いたとき |
| `handle_host(msg)` | PC画面から1件届いたとき |

### なぜ分けるか

`game/logic.py` は FastAPI も WebSocket も import していない。
そのためサーバーを起動せずにルールを検証できる。

```bash
./.venv/Scripts/python.exe -m unittest discover -s tests -t . -v
```

### 流れ

```
スマホ ──{"type":"roll"}──> game_common: server.py
                              |
                              v
                     game_common: hub.py ──> game/logic.py の handle()
                              |                  |
                              |          [Event(...), Event(...)] を返す
                              v                  |
                          宛先ごとに送信 <────────┘
                              |
                    ┌─────────┴─────────┐
                    v                   v
                 PC画面              全スマホ
```

`game/logic.py` は「誰に何を送るか」を `Event` で返すだけで、送信そのものはしない。
共通側の `Hub` がそれを受け取って実際のWebSocketに流す。

### 状態の持ち方

差分ではなく、毎回 `state` をまるごと配る。

```python
{"type": "state",
 "phase": "playing",              # waiting / playing / finished
 "start_money": 1000,             # はじめの所持金（ルールの説明に使う）
 "card_limit": 3,                 # 手札の上限（超えたら捨てる。パーツは数えない）
 "stages": [{"name": "地上", "mark": "🌍"}, ...],   # 階層。名前は画面ではなくここが決める
 "part_kinds": [{"id": "right", "label": "右翼"}, ...],
 "last_climb": {"seq": 2, "id": "p1", "name": "アオイ", "layer": 2, "heaven": false},
                                  # 直前に登った記録（無ければ null）。最上階では heaven が true（天国へ旅立った）
 "boards": [                      # 階層ごとの盤。boards[0] が地上
   {"size": 30, "half_pos": 15,            # マス数（29 の次は 0）と、半周のマスの位置
    "salary": 200, "half_bonus": 1000,     # その階層でもらえる給料と半周ボーナス
    "squares": [{"kind": "gain", "value": 200, "label": "もらう +200円"}, ...]}, ...],
 "cleared": null,                 # 天国へ旅立った（クリアした）人のID。いなければ null
 "turn": "p1",                    # いま手番のプレイヤーID
 "last_roll": {"seq": 7, "id": "p1", "name": "アオイ", "value": 4, "values": [4], "bonus": 0,
               "from": 25, "land": 27, "to": 0, "shift": 3, "effect": "ワープ +3",
               "before": 1200, "salary": 200, "half": 0, "gain": 0, "blocked": 0, "drew": false,
               "money": 1400, "layer": 2},    # layer は振ったときの階層
 "players": [{"id": "p1", "name": "アオイ", "color": "#ff5c7c",
              "pos": 0, "money": 1400, "resting": false, "rank": 1,
              "cards": 2, "bonus": 0, "dice": 1,
              "layer": 2, "parts": 1}, ...]}    # layer は階層（1 = 地上）、parts はパーツの個数
```

`rank` は所持金の多い順の順位で、毎回サーバーが計算して入れる。
`players[].cards` は**手札の枚数だけ**、`players[].parts` は**パーツの個数だけ**。何を持っているかはここには入らない。

### 手札は持ち主にしか配らない

カードが入ったことで、**参加者に同じものを配れなくなった**。
そこで参加者へは1人ずつ、本人の手札を足した `state` を送る。

```python
to_hosts(state)                 # PC画面へ。手札の中身は入っていない
to_player("p1", state + you)    # p1 へ。p1 の手札だけが入る
to_player("p2", state + you)    # p2 へ。p2 の手札だけが入る
```

本人にだけ届く `you` の中身。

```python
"you": {"id": "p1",
        "hand": [{"uid": "c3", "kind": "advance", "label": "+2マス",
                  "desc": "つぎにサイコロをふるとき、…", "value": 2, "passive": false}, ...],
        "parts": {"right": 1, "left": 0, "engine": 2},   # パーツごとの数
        "can_climb": false,                          # 3種類そろっていて登れるか
        "over": 0,                                   # 捨てないとふれない枚数
        "drew": {"uid": "c3", "label": "+2マス", ...}}  # 直前に自分がひいたカード（演出用）
```

`uid` はカードを1枚ずつ見分ける番号。並び順（添字）で「この1枚を使う」と指すと、
指示が届くまでに手札が変わったとき別のカードを捨ててしまうので、必ず `uid` で指す。

手札を `state` に入れてしまうとPC画面と他の参加者にも見えてしまうので、
公開分を作る `state()` と、本人宛に足す `_private()` を分けてある。

画面側は受け取った `state` を描き直すだけでよく、表示がずれない。
途中から `/host` を開いても、その時点の盤面がそのまま出る。

`last_roll` の位置と金額はアニメーション用に分けてある。

| | 意味 |
|---|---|
| `from` | 振る前の位置 |
| `land` | 出目ぶん進んだ位置（マスの効果を受ける前） |
| `to` | マスの効果まで反映した最終位置 |
| `shift` | マスの効果で動いた歩数（戻るときは負） |
| `before` | 振る前の所持金 |
| `salary` | スタート通過でもらった合計（振った階層の額） |
| `half` | 半周を通過してもらった大金（0 なら通過していない） |
| `gain` | マスの効果で増減した額（0円で止まった場合は実際に動いた額） |
| `money` | 振った後の所持金（= `before + salary + half + gain`） |
| `value` | 実際に進んだ歩数（出目の合計 + カードで足したぶん） |
| `values` | サイコロの出目。カードで2個になっていれば2つ入る |
| `bonus` | カードで足した歩数 |
| `blocked` | おまもりで払わずにすんだ額（0 なら発動していない） |
| `drew` | カードをひいたか。**何をひいたかは入らない**（本人の `you.drew` にだけ入る） |

出目ぶん（`value` 歩）を1マスずつ歩き、効果マスなら一拍おいて `shift` 歩を歩く。
歩いている途中でスタートを踏むたびに `salary` ぶん所持金の表示を増やす。
`seq` は振るたびに増える通し番号で、画面側が「新しい出目か」を判定する。
再読み込みや途中参加のときは演出せず、いきなり最終状態を描く。

### ゲームを足すには

`game/logic.py` の `handle()` に分岐を足す。状態は `Game` のフィールドに持たせる。
共通側（`../game_common`）は触らなくてよい。

```python
if kind == "roll":
    return self._roll(player)
elif kind == "answer":            # 例: クイズの回答
    return self._check_answer(player, message["choice"])
```

盤だけ変えたいなら `game/board.py` の `LAYOUTS` を書き換える。

### 通信の中身

スマホ → サーバー

```json
{"type": "roll"}                サイコロをふる（自分の番でなければ無視される）
{"type": "use", "uid": "c3"}    カードを使う（自分の番だけ。効果は次にふるとき出る）
{"type": "discard", "uid": "c3"} カードを捨てる（溢れているときだけ）
{"type": "climb"}               パーツ3種類を使って1階層登る。最上階では天国へ旅立つ（クリア）
                                自分の番だけ。そろっていなければ無視される
{"type": "start"}               ゲーム開始（遊んでいる最中は無視される）
{"type": "finish"}              ここで終了（いまの所持金で順位を決める）
{"type": "leave"}               退出ボタンを押した
```

開始と終了はスマホからもできる。PC画面の前に人がいなくても遊べるようにするため、
`start` と `finish` はPC画面と同じ処理を呼ぶ。

PC画面 → サーバー

```json
{"type": "start"}               ゲーム開始（全員スタート・1,000円に戻して手番を先頭へ）
                                遊んでいる最中は無視される
{"type": "finish"}              ここで終了（いまの所持金で順位を決める）
{"type": "reset"}               開始前の状態に戻す
{"type": "kick", "id": "p2"}    その参加者を切断する
```

QRの表示はサーバーを通さない。`phase` が `finished` に変わったのをPC画面が
見つけて自分で出すだけなので、状態も通信も増やしていない。

サーバー → PC画面

```json
{"type": "state", ...}    公開してよい分だけ（手札の中身は入らない）
```

サーバー → スマホ（その人だけ）

```json
{"type": "state", ..., "you": {...}}  上と同じ内容 + 自分の手札
{"type": "joined", "you": {...}}   参加できた。自分のIDと色が入る
{"type": "left"}                   退出が受理された（この直後に切断される）
{"type": "kicked"}                 PC画面から切断された
```

### 切断の扱い

`left` / `kicked` を送ったあと、サーバーがWebSocketを閉じる。

ゲームロジックは `Event(..., close=True)` で「閉じてほしい」と示すだけで、
実際の `ws.close()` は共通側の `Hub` が行う。ここでも層は分かれている。

スマホ側は、退出・キックのときだけ自動再接続を止めて名前入力画面に戻る
（iOSの画面ロックによる切断とは区別している）。

## PC画面とスマホで表示を揃える仕組み

同じ内容を2つのHTMLに別々に書くと、片方だけ直して食い違う。実際に起きた。

- サイコロのCSSを片方にだけ変更 → PC側だけサイコロが消えた
- 位置の文字列を別々に組み立て → 表示がずれた

そこで **両画面が使う部分は `static/shared/` にしか置かない**ことにした。

| 直したい場所 | 触るファイル |
|---|---|
| 位置・出目・金額・順位・カードの文言 | `shared/format.js` |
| サイコロの見た目 | `shared/dice.css` |
| サイコロの動き | `shared/dice.js` |
| 効果音 | `shared/sound.js` |
| 移動の速さ | `shared/anim.js` |
| 接続・再接続のしかた | `../game_common/mobilelink/static/conn.js`（両画面で共通） |

位置の表示は `posLabel()`、金額は `moneyLabel()` だけが作る。PC画面の一覧もスマホの見出しも同じ関数を呼ぶので、
文言も数字も食い違いようがない。`node --test "tests/js/*.test.mjs"` がこれを検証している。

### 表示をサーバーの値で締める

演出中は表示用の仮の位置を使うが、**演出が終わったら必ずサーバーの状態で描き直す**。

- PC画面: `drawPanel()` と `drawTokens()`
- スマホ: `drawStatic()`

途中で切断されても、次の状態が届けば正しい値に戻る。

### 注意: サイコロのCSSに足してはいけないもの

`.cube` に `filter` / `opacity` / `overflow` を足さないこと。
これらは `transform-style: preserve-3d` を無効化し、立方体が平坦化して消える。
影が欲しいときは `.face` 側の `box-shadow` を使う（`shared/dice.css` に注意書きあり）。

### ブラウザのキャッシュ

HTML・JS・CSSは `Cache-Control: no-store` で配っている。
画面を書き換えたのに古いJSが動き続ける事故を防ぐため。通常の再読み込みで必ず最新になる。

### BGM

PC画面だけで、`phase` が `playing` の間だけ流す（`shared/sound.js` の `setBgm()`）。
スマホでは流さない。同じ部屋で二重にずれて聞こえるため。ミュートボタン（🔊/🔇）と連動する。
ブラウザは画面を触るまで音を鳴らせないので、操作するまで待ってから鳴り出す。

曲は [OpenGameArt](https://opengameart.org/content/short-loops-background-music-pack) の
hernandack「Swinging Sweet」（CC0・クレジット不要）。差し替えるときは `audio/bgm.ogg` を置き換える。

### 階層ごとの背景

背景は階層で変わる（`shared/stages.css`、画像は使わずCSSだけ）。

| 階層 | 背景 |
|---|---|
| 1 地上 | 夕暮れの空と丘 |
| 2 天空 | 青空と、ゆっくり流れる雲 |
| 3 宇宙 | 星・星雲・惑星、またたく星 |

- **スマホ**: 自分の階層の背景になる
- **PC画面**: いま手番の人の階層の背景になる（手番が移ると1.4秒かけて入れ替わる。
  終了後は最後に振った人、開始前は地上）
- `<body data-stage="…">` の値を書き換えると切り替わる。階層の数を増やすときは
  `stages.css` に `.s4` と `body[data-stage="4"]` の規則を足し、両HTMLの `#stagebg` に `<i class="s4"></i>` を足す
- `body` に `background` を付けないこと（付けると背景が隠れる）。テストが見ている
