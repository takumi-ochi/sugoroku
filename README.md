# 接続テスト（Windows親機 ⇄ iOS / Android）

スマホでQRを読む → 名前を入れて参加 → ボタンを押すとPC画面に即反映、までの最小構成。

## 起動

```powershell
.\run.ps1
```

初回は venv 作成と依存インストールが走ります。手動でやる場合:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

起動するとターミナルにQRコードと2つのURLが出ます。

- **PC画面** `http://localhost:8000/host` をブラウザで開く（QRもここに出ます）
- **スマホ** 同じWi-Fiに繋いだ状態でQRを読む

## 動作確認の手順

1. PCで `/host` を開く → 右上が緑の「サーバー接続済み」になる
2. スマホでQRを読む → 名前を入れて「参加する」
3. PC画面にカードが現れる
4. スマホのTAPボタンを押す → PC画面の数字が増え、カードが光る
5. スマホのブラウザを閉じる → カードが消える

ここまで通れば、双方向のリアルタイム通信ができています。

## 繋がらないときは

| 症状 | 原因と対処 |
|---|---|
| スマホでページが開かない | **同じWi-Fiにいない**のが大半。スマホのモバイル通信をオフにして確認 |
| 同上 | Windowsファイアウォール。初回の確認ダイアログで「プライベート ネットワーク」を許可。見逃した場合は「Windows セキュリティ → ファイアウォールとネットワーク保護 → アプリケーションの許可」でPythonを確認 |
| 同上 | ネットワークプロファイルが「パブリック」になっている。設定 → ネットワーク → Wi-Fi → プロパティ で「プライベート」に |
| ターミナルのIPが `127.0.0.1` | ネットワーク未接続。Wi-Fi/有線を確認 |
| ゲストWi-Fi / 社内Wi-Fi | 端末間通信がブロックされている（AP isolation）。スマホのテザリングにPCを繋ぐと回避できることが多い |
| iOSで画面ロック後に反応しなくなる | 対処済み。復帰時に自動再接続します（1秒以内） |

## 構成

```
main.py              サーバー（FastAPI + WebSocket）
static/host.html     PC画面
static/player.html   スマホ画面
```

### 通信の中身

スマホ → サーバー

```json
{"type": "tap"}
```

サーバー → PC画面

```json
{"type": "roster", "players": [...]}       全員の状態（参加/退出のたびに配信）
{"type": "join",   "player": {...}}
{"type": "leave",  "player": {...}}
{"type": "tap",    "player": {...}}
```

ゲームの状態は `main.py` の `Hub` が一元管理しています。ここにゲームロジックを足していく形になります。
